# ARG-01 execution protocol and failure gates

**Status:** CPU reference comparison with RRC-19 frozen checkpoint and independent EvalMath oracle. No Qwen3.5 or 27B model inference in the current results. This file was written during the implementation, not before the earlier RRC experiments.

1. Pin the EvalMath source SHA-256 locally, then its exact remote commit when merged, four RRC-19 checkpoint bytes and the deterministic generator seed. The EvalMath oracle is independent of the RRC model code. Refuse altered sources and unpinned responses.
2. Generate the reference 36-case calibration and 192-case test/control roster. Learned checkpoints are frozen; no test or calibration gradient updates, parameter selection or architecture changes. Test cases have unique public signatures apart from six explicitly duplicated future pairs.
3. Use RRC-18's certified finite-degree classes as the common neural-output decoder. A 6,240-weight balanced RRC-19 GRU and same-size skewed/shuffled GRUs, plus 6,235-weight feedforward control, rank classes from the public demos/topology. They perform **zero candidate interpreter previews**. Test up to twelve distinct class representatives; include the class-size prior under the same twelve-query budget and the complete-class and 64-syntax higher-resource baselines.
4. Every candidate query must run two independent exact demonstrations through coefficient 12. Only certified proposals count as accepted. Grade a new query's withheld coefficient-32 future afterward. Count the number of paid candidate checks, exact integer-loop proxy, model forward MACs, class compiler executions and wall time separately. Never equate the latter arithmetic proxies.
5. Reject all known negatives within the 64-program grammar. For each visible-equal future pair, every model must issue the same query trace. Full exact search must have exactly one incorrect future per pair; exact observed-prefix validity is not a theorem of infinite series equality.
6. Record by-family accepted and future-correct totals, paired differences, and separate known/novel source aggregates. A positive learned-recurrence claim requires improvements over feedforward, class-size ordering and complete exact search at comparable **total** compute; failure is a published result.
7. The optional external model path accepts depth 0/1/2/4/8 plus a pinned revision and input digest, and fails on missing/invalid model evidence. The JSONL model exchange supports actual locally run Qwen/looped checkpoints, while the evaluator never asserts that model-declared depths are physical recurrence until hooks/forward traces verify them.

All CI tests and replay run on CPU using standard-library Python plus the existing repository sources. The CI workflow checks out the full pinned EvalMath commit and verifies its oracle source hash. In source-only local snapshots, the Git commit field is explicitly unresolved until the EvalMath integration is merged. It does not train, download weights, request GPU instances, or score unprovided external-model answers. A future Qwen experiment must pin task split, checkpoint, inference implementation and causal intervention settings *before* looking at its held-out results.
