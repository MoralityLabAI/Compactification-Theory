# NOR-56: version-bound signed compact-v2 batch-table verifier

The [first prospective preregistration](REGISTRATION.md) was frozen at commit **b186ee7478f27230478b099d7091b25817839464**, before new NOR56 source generation or first CPU timing. It follows the immutable [NOR55 original 4/5 engineering FAIL](../nor55_compact_witness/RESULTS.md), where the signed compact-v1/JSON verification ratio was 0.851483x against a registered <0.85x criterion. NOR56 is a fresh source-locked experiment with distinct thresholds.

The [canonical compact-v2 payload](codec_v2.py) contains a minimal canonical reduced count followed by a contiguous **big-endian 16-bit sign/length table** and tightly concatenated minimal unsigned magnitudes. One C-backed `struct.unpack_from` decodes all supported coefficient widths, while the original NOR55 v1 decoder uses Python varint scans per coefficient. Both reconstruct identical builtin signed integers, exact zeros outside registered support, and the original full NOR45 Merkle root. Zero/negative-zero, leading-zero magnitude, endian, count/length, extra/truncated data and 32768-bit violations are rejected.

The [signed v2 envelope](signed_v2.py) reuses NOR55's trusted full source/session context, canonical envelope parse and independent pinned verifier key, with **a distinct Ed25519 domain** and explicit signed protocol/format version. Signed header, source-vector SHA, trusted source ID, full length, stride, expected full Merkle root, provider fixture, unique 256-bit nonce and monotone session sequence remain mandatory. The independent NOR53 fast GMP verifier checks full original source/witness caps, exact signed inverse identity and full original root before any nonce is marked accepted. Existing NOR55 signed v1 and signed JSON implementations remain byte-identical and unmodified.

The [first 60-source cohort](cohort.py) uses NOR56/SOURCE/v1 with the same fixed 2×3×5×2 public grammar as NOR55 and SHA-excludes **all 288 original NOR51–55 first source IDs** from their immutable SHA-pinned ZIPs. A separate upstream public-only job publishes the exact first source SHA before a dependent CPU job generates an inverse or timing information.

The first [CPU benchmark](benchmark_cpu.py) executes four complete-output/full-root arms across five source/repetition-seeded interleaved repeats each: NOR52 compressed native R, NOR55 signed compact-v1, NOR55 signed decimal JSON, and NOR56 signed compact-v2. The original full native reference witness and all signed fixture envelopes are created outside the timed verifier calls. Their generation/encoding/signing costs and full wire sizes are recorded independently. Pre-timing and timed calls must produce exactly identical full vectors and roots and pass every signed challenge once.

The **five preregistered first gates** cover two fixed 16-source sparse-m3073 verifier ratios: v2/v1 strictly below 0.92x, v2/JSON strictly below 0.82x; complete signed v2/v1 envelope bytes below 1.05x on 48 sparse sources; 60/60 exact vectors/full Merkle roots and hostile signed version/source/replay/codec controls; and source-first SHA/288 historical exclusions/five-repeat/bound/reentrant/immutable evidence. An original PASS needs 5/5. Preserve every original FAIL unchanged.

The separately [instrumented phase diagnostic](phase_diagnostic.py) runs only **after** registered whole-operation timing per source, reproducing the pinned signed verifier output/root while measuring header/replay, Ed25519 verification, canonical payload decode, original support/caps, exact GMP identity and original full Merkle root. Its phase timings cannot replace the original registered gates.

**Security scope:** signed test fixtures are generated using a deterministic private key **publicly embedded** in NOR55; this demonstrates conditional integrity and replay checks for synthetic public exact integer witnesses, not secure deployed provider keys, zero-knowledge or succinctness. At m3073 this is outside original NOR45 signed program grammar. Signing-side work and actual network transport are excluded from primary verifier-only CPU times.

**First source-only/CPU trigger:** prospectively registered source-free tests passed after correcting a toy length-boundary assertion before source generation. The registration SHA and original five gate thresholds have not changed. This commit instructs the upstream CI job to SHA-freeze the first 60 public-only identities, then permits the dependent four-arm five-repeat CPU job. All resulting first evidence, including a FAIL, must remain immutable.
