# RRC-11: finite graph identification, exact witnesses and information limits

Let \(F(q)\in 1+q\mathbb Z[[q]]\). The public graph vocabulary contains the unit-preserving unary maps \(I(F)=F\), \(N(F)=F(-q)\), \(S(F)=F(q^2)\), \(R(F)=1/F\), and a binary join \(M(A,B)=AB\). A graph is a three-node fork/join descriptor \(G=(u,v,w)\), interpreted as \(w(M(u(F),v(F)))\). There are exactly \(4^3=64\) syntax graphs. Shared input and branch multiplication make this a small *operator graph* rather than a single operator token; the graph topology itself is a fixed scaffold.

All arithmetic uses truncated integer power series. Inversion exists because the constant coefficient is one and obeys \(r_0=1\), \(r_n=-\sum_{j=1}^{n}f_jr_{n-j}\). Multiplication uses convolution \(c_n=\sum_{j=0}^{n}a_jb_{n-j}\). Degree truncation commutes with every graph in this vocabulary, so evaluating a candidate through observed degree 12 is a sound finite prefix test.

**Bounded completeness:** Full search enumerates all 64 candidate graphs and compares each candidate's outputs on both demonstrations through degree 12. If it returns a graph, that graph is an exact finite witness. If it exhausts the grammar, there is no compatible program among the 64 graphs for those observed demonstrations. The claim is *relative to the finite graph class*. Other graphs may exist.

**Ambiguity:** Graph equivalences include branch commutativity, inverse cancellation, and occasional input-specific coincidences. Recovery is scored by observational equivalence and future output, never by matching a hidden syntax label. A target mutant changing only degree 15 has identical demonstrations and query. Every deterministic proposal returns the same output for both members of a pair, so at most one can match both futures. Eight such pairs are included.

**Learning boundary:** The four fitted preview-ranking weights see features derived from executing all 64 **public** candidate graphs through degree four on both demonstrations. This grants the learner the operators' semantics and pays for 512 primitive calls per case just for previews. The untrained comparator uses precisely the same executions. The results measure ordering with a bounded four-attempt exact checker, not neural construction of a new graph vocabulary.

**Cost model:** Each candidate evaluation counts four primitive calls for the two unary branches, multiplication, and post map. It uses a conservative nominal proxy \(3(T+1)^2\) integer coefficient operations per evaluated candidate per demonstration. Full search short-circuits each candidate on the first demo mismatch, which matters for cost. Every guided method pre-executes 64 candidates on *both* demonstrations at preview degree four, adding 512 calls and \(64\cdot2\cdot 3\cdot5^2=9600\) nominal operations before full checks. Integer bit complexity, Python runtime, model fitting, and verifier overhead are outside this proxy. The fixed three-token graph code needs six syntax bits (two bits per unary node), excluding the entire interpreter and shared graph scaffold.
