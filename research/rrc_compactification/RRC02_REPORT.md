# RRC-02: tiny recurrent student for symbolic partition grammars

**Run date:** 2026-11-09. **Status:** three CPU-trained classifiers, frozen
checkpoints, deterministic evaluation receipt and exact negative controls.
This is a deliberately narrow pilot of the larger RRC-02 protocol in
[`PROTOCOL.md`](PROTOCOL.md). No pretrained LLM, novel infinite identity,
new symbolic theorem, or automatic proof discovery is claimed.

## What was trained

Given only exact counting coefficients `f_0..f_64`, the immutable RRC-01
Euler inverse constructs exponents `a_1..a_64`. For each candidate period
`m=1..12`, the student classifies each residue's observed exponents as
`all-zero`, `all-one`, or `mixed/invalid` using six precomputed statistics:
mean, mean square, first, last, count, and average successive absolute
change. Inputs are clipped to `[-3,3]` and scaled. The features directly
expose strong information about periodicity; the learner is a *restricted
rule classifier*, not a blind algebra discovery model.

The recurrent student is a 363-parameter `tanh` network with a shared
hidden-state transition. It sees the same full feature vector at recurrent
steps `0/1/2/4/8`, making the sweep a computation-depth ablation without a
change in observed evidence. Its near-parameter-matched 371-parameter
feedforward control has two hidden layers. A second 363-parameter recurrent
model trains on independently permuted training labels and retains the
same label frequencies. All three use CPU Adam and 360 batches of 512
train-only feature rows, with fixed seeds. The single local training run
used PyTorch `2.10.0+cpu`, Python `3.13`; export is floating-point JSON.
The standard-library evaluator replays every checkpoint without PyTorch.

The model proposes a candidate residue mask at a chosen modulus. A separate
frozen checker recomputes the unrestricted-part generating function through
degree 64. Only exact-prefix matches are accepted. This shared verifier
supplies the executable certificate, and **is not itself generated by the
student**. The smallest verified modulus wins. Degrees 65–128 are never
read by training, model inference, model selection or the verifier.

## Data splits

| Partition source | Split | Cases | Source | Condition |
|---|---|---:|---|---|
| periodic Euler products | Train | 96 | moduli 2,3,4,6,8,9,10,12 | binary residue masks |
| finite-defect products | Train | 96 | same moduli | flipped `a_n` inside training prefix |
| colored-part products | Train | 32 | same moduli | at least one Euler exponent equals 2 |
| distinct parts | Development | 8 | local gap 1, minima 1–8 | entirely held-out local family |
| gap-separated partitions | Test | 12 | local gaps 2,3,4, minima 1–4 | no such local family in training |
| unseen modulus products | Test | 24 | moduli 5,7,11 | product generator seen, moduli excluded from training |
| indistinguishable collision pairs | Test | 8 | four period-5 baselines plus four late mutants | mutation at `K>64` |

All cases and masks come from frozen deterministic RNG streams. Test product
masks use a separate seed stream. The 224 training cases yield **17,472**
per-residue training examples across candidate moduli. Hyperparameters and
roster are held fixed for the run. Each local-gap test uses the recurrence
from RRC-01, not the product generator used for the training teacher.

## Reproduced measurements

| Metric on all 44 test cases | Recurrent, 0 passes | Recurrent, 8 passes | Feedforward | Shuffled-label |
|---|---:|---:|---:|---:|
| Cases agreeing with exact prefix enumerator | 44 | 44 | 44 | 10 |
| Accepted candidate programs | 34 | 34 | 34 | 0 |
| Correct predictions on the held-out span | 30 | 30 | 30 | 0 |
| Accepted certificates with failed held-out predictions | 4 | 4 | 4 | 0 |
| Proposals rejected by exact prefix verifier | 6 | 5 | 5 | 528 |

The 30 exact successful predictions are: the two Rogers–Ramanujan local-gap
families at minima 1 and 2, all 24 modulus-disjoint Euler-product cases,
and the four unperturbed collision baselines. The other ten local-gap
cases correctly abstain. The four mutated collision cases pass the exact
**prefix** certificate and fail at the planted hidden degree 65, 73, 96,
or 112. This is predicted by the [prefix-indistinguishability theorem](RRC02_THEOREMS.md).

All five recurrent-depth settings gave **the same 44/44 exact-enumerator
agreement and 30/44 held-out exact cases**. The feedforward model achieved
the same result with eight more parameters and a single evaluation pass.
Recurrence contributed **no observed improvement in predictive accuracy**.
The shuffled-label control proposed many invalid masks; the exact checker
rejected every proposal on the test set. These figures describe one frozen
toy roster, not population generalization or model capabilities elsewhere.

## Resource accounting and baselines

* Recurrent: `363` FP32 parameters = `11,616` bits of bare parameter
  storage; feedforward `371` = `11,872` bits. Shuffled `363`.
* Inference on the 44 test cases at recurrent depth 8: `2,400,264`
  estimated dense multiply-accumulates, excluding nonlinearities and
  the exact Euler inverse, coefficient verification, interpreter, and
  Python overhead. The feedforward student uses `610,878` estimated MACs.
* Each successful period-5 rule has the RRC-01 illustrative grammar code
  length of `10` bits, excluding the shared grammar decoder and full search
  procedure. The learned model storage is charged separately.
* The exact symbolic enumerator finds every accepted short rule directly
  from the unique finite Euler exponents, with **no trained parameters**.
  It is a stronger baseline here, and its short finite certificate requires
  fewer candidate predictions than the neural pipeline.

No native GPU inference was used. There are no wall-clock cross-environment
speed claims. These CPU MAC counts exclude training optimizer state and exact
arithmetic big-integer complexity.

## Reproduce

From the repository root, using Python 3.10+ and only the standard library:

```bash
python -m unittest discover -s research/rrc_compactification -p 'test_rrc02.py' -v
python research/rrc_compactification/rrc02.py --check
```

To repeat the **training** rather than just replay the frozen weights,
install PyTorch (locally tested with `2.10.0+cpu`), then:

```bash
python research/rrc_compactification/train_rrc02.py --steps 360 --batch-size 512
python research/rrc_compactification/rrc02.py --check
```

After retraining, the last command deliberately fails if the checkpoint
bytes differ from the reviewed receipt. Review and regenerate it with
`python research/rrc_compactification/rrc02.py` before committing changed
results. The canonical receipt records source hashes, checkpoint hashes,
training-roster hash, every per-case decision and per-family aggregates.
The CPU-only CI uses **frozen weight replay**, never downloads Torch or
launches a training job.

## Next falsifiable extension

RRC-03 should remove the precomputed Euler features and expose raw,
scale-normalized coefficients to both learners. Generate held-out local
rules with product forms outside a predeclared modulus-12 binary mask, and
require calibrated abstention under complete information limits. Keep
the exact symbolic pipeline as a baseline and charge any external
transforms/proof routines to total compute. Depth-sensitive tasks must
preserve the evidence and parameter budget across all loop counts.
