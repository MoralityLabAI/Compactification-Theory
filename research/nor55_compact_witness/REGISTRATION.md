## Exact supported problem and trust limits

Given public F(x)=H(x^s), F[0]=1, s in {1,4,8}, the unique inverse in integer formal series modulo x^m has supported coefficients only at multiples of s. The public full source and untrusted inverse are normalized builtin signed integers. The receiver reconstructs the **complete full-length m vector** with exact zero coefficients, enforces the **original full** NOR47 32,768-bit-per-coefficient and 120,000,000 packed-bit resource caps, checks all original source/support positions, independently verifies the signed inverse identity with the NOR53 fast compressed GMP kernel, and computes the original complete NOR45 Merkle root.

This is an **algebra-only** transparent witness service on synthetic integer series. At m3073 the NOR45 native signed-program authority grammar is not extended. A pinned deterministic Ed25519 research-fixture key authenticates a message **conditional on trusting that key**; it does not prove the publisher honest, external future truth, a deployed key ceremony, zero knowledge or succinctness. Genuine off-host networking is not measured in the primary.

## Two exact wire formats and signed envelope

Implement a canonical **compact-v1** binary payload containing exactly L=floor((m-1)/s)+1 reduced coefficients, each as one sign octet (0 positive/zero, 1 negative), a canonical minimally encoded unsigned varint of big-endian magnitude length, then a minimal unsigned big-endian magnitude. The reduced coefficient count is a leading canonical varint and payload uses a fixed domain/version magic. Reject non-minimal magnitude, signed negative zero, truncated/overlong varint, missing/extra bytes, invalid sign, overcap values and any L mismatch. Expand with exact zeros to full m. The comparison **json-v1** payload is NOR54's canonical full-length JSON array of decimal signed integer strings; decode canonically and apply the same original source/support/full resource checks. A compact encoding and its comparison JSON must represent identical full values.

Wire envelopes are length-delimited and byte-canonical: fixed domain magic + 4-byte big-endian canonical JSON header length + sorted compact JSON header + **raw payload bytes** + 64-byte Ed25519 signature over a domain-separated exact preceding byte string. The header binds protocol/version, payload format, payload byte length and SHA256, full source input SHA256, NOR55 source-record SHA256, expected full output Merkle root, full length m, independently specified stride s, trusted provider fixture identity, session identifier, monotone sequence index, and 256-bit fresh verifier-issued nonce. The receiver checks header exact keys/canonical serialization, an externally pinned Ed25519 *public* key, payload SHA/length, all header fields against an **independent immutable trusted source/session context**, and the full result root; it then verifies the exact algebraic inverse. The receiver tracks accepted (session, nonce, sequence) tuples and rejects replay/nonmonotonic sequence. Invalid requests must not advance the guard. The fixture private key is deterministic from a labeled SHA256 test seed and **must never be reused as a real provider key**. Do not accept self-supplied public keys or expected roots as trust anchors. Source/session contexts are issued outside timing, while actual envelope parse, signature verification, payload decode, signed algebra/root verification and replay guard checks are charged within the authenticated verifier arms.
