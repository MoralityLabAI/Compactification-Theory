# Local rank barrier despite logarithmic communication

For Index_k, query-and-response uses ceil(log2 k)+1 transmitted bits. But if a static affine threshold readout must answer each address exactly for every independent bipolar memory vector, its address-by-input weight matrix W has strict row diagonal dominance after reordering addresses and normalizing response signs. Indeed positive/negative worst-case margins give w_ii>=S_i-b_i and w_ii>S_i+b_i, S_i=sum_{j!=i}|w_ij|; hence w_ii>S_i. Maximal-coordinate kernel argument gives rank W=k. Therefore a rank-d factorized static readout cannot exactly retrieve every coordinate when d<k. This proof is independent of communication budget. It applies to affine threshold readout only; recurrence/nonlinearity and context-conditioned routing may evade this restriction.

For a structured sparse router, one signed coordinate index per address suffices; dense algebraic rank and actual storage are not identical resources. Report stored bits (indices and signs), local compute, rank, message bits and exact-domain certificate separately. A full-rank sparse permutation matrix is cheaper than a generic dense rank-k matrix. Proposed comparison: frozen learned address map, direct correlation-selected sparse row, factorized rank-half and rank-full linear retrieval, and recurrent GRU readout. Use exact diagonal-dominance margins as a proof witness only with exact coefficients or certified numerical bounds; held-out accuracy alone is empirical. The original 32-wide GRU's factorized scalar message head does not instantiate this static k-address weight-matrix rank theorem.
