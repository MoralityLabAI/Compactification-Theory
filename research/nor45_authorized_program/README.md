# NOR-45: Authorized program execution as an output-witness premise

[Design issue #241](https://github.com/MoralityLabAI/Compactification-Theory/issues/241)

This is a **historical-only** engineering and security experiment built from the SHA-locked 64 paired-world original NOR42 sources. The input roster, original clean/hidden futures and NOR44 source/session protocol are reused; **zero new prospective NOR45 source identities or registered science gates** are generated.

The provider receives an **independently signed program statement** after the proposer freezes its full-output prediction in a NOR44 verifier-signed receipt. The statement commits to the original exact RRC25 six-tuple, its optional NOR42 late suffix `βX^(D+32)T(F)`, the full normalized query-input hash, source SHA, observed degree D, future length m, unique verifier session, proposal receipt and the resulting m-output coefficient Merkle root. The program signer is **a separately pinned program authority**, distinct from the signed-output provider and signed-session verifier.

The independently coded verifier validates that program statement under the pinned program authority's public key, reconstructs every coefficient using its own finite-integral-series interpreter, rebuilds the source-index-bound NOR43 Merkle root with independently implemented hashing/framing, and checks that it equals both the authorized program statement and NOR44's source/session-bound provider root. It then uses the exact verifier-selected k16 Merkle openings and precommitted proposal from NOR44. For the hidden program, a public-prefix-only clean proposal gets rejected iff one of the sixteen checked indices lies in the original NOR42 hidden discrepancy support. The full-execution root check is required **before** the first reference challenge.

**Premises:** Signature unforgeability, hash collision/second-preimage resistance, trusted verifier state and key provisioning, an authorized authority selecting the *right real-world program*, and the actual query/program execution semantics. The deterministic Ed25519 keys and challenge coins in this reference implementation are public test fixtures. Recomputing the entire output is **not** a succinct proof, SNARK, zkVM, or an on-chain verifier.

The historical smoke tests three distinct fraud boundaries per archived source: (1) an honest program authority chooses the existing hidden true program and the output provider signs the correct hidden Merkle root; (2) a dishonest authorized output provider signs the wrong clean output, violating the separately authorized hidden program; (3) a dishonest but authorized program authority signs the *wrong clean program*, and the provider faithfully signs the clean output. Case (2) fails full recomputation even though its output-provider signature is valid. Case (3) passes both crypto and faithful execution but differs from the historical synthetic true hidden world, demonstrating that execution integrity alone cannot supply semantic truth. A model-controlled self-signed clean-program attestation fails the independently pinned authority key.

A fully context-bound signed certificate includes the NOR44 session nonce and signed proposal receipt digest. Source SHA, D, m, full query hash, provider key ID, program authority ID and semantics version cannot be replayed across contexts without rejection. The verifier must reject malformed integer encoding, unsupported operations/parameters and mismatched roots.

Cost receipts separate the authorized program certificate, signed provider reference and individual Merkle proof bytes from full-vector recomputation time. All results are grouped by original NOR42 64 paired source identities. Any new NOR45 prospective outcome would need another pre-data registration and fresh source families.
