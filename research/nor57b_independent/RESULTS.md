## Exact signed acceptance and research scope

Every arm parses and authenticates an **identical complete NOR56 compact-v2 signed envelope**, verifying the pinned research key fingerprint, trusted full source/source SHA, original expected root, exact unit/support/coefficient/packed caps, monotone verifier-issued nonce and session, and a complete original full NOR45 Merkle root before accepting. The native arm independently recomputes a reduced exact reciprocal from trusted source and compares every reduced/full supplied signed coefficient. The GMP arm checks exact signed no-carry polynomial identity. The frozen selector reads only authenticated full public length, stride and actual coefficient bit length, using the **same rule as original NOR57**. First source-level five-repeat timing samples, roots, source hashes and signer generation/serialization costs are all preserved in the raw first JSON.

This tests a transparent nonsuccinct exact integer algebra witness with a **public deterministic research Ed25519 fixture seed**, not real secure source or remote publisher trust. m3073 remains outside original NOR45 signed-native program grammar. Deployed source/session authority, actual off-host network costs, and true-world provider honesty remain external. A follow-up must be independently preregistered if experimenting with selector routing to increase workload-wide savings; it cannot retroactively change this NOR57B first 4/5 FAIL.

## Post-hoc idealized per-source routing frontier

*Descriptive addendum after the first result was frozen and merged. It is excluded from the preregistered five-gate decision and changes none of the first raw bytes or registered FAIL.*

Let \(t_G(s)\) and \(t_N(s)\) be the five-repeat source medians of the **always-GMP** and **always-native** signed-v2 verifier arms for source \(s\), with the identical authenticated input bytes and original full Merkle root. An unrealizable timing oracle that knows both measured runtimes in advance and has zero dispatch cost could choose

\[
t_*(s)=\min\{t_G(s),t_N(s)\}.
\]

The exact first source-median sums from the immutable NOR57B CPU JSON are:

| Same 60 public inputs | Sum of source-median whole-operation time | Ratio to always GMP |
| --- | ---: | ---: |
| Always fast GMP | **2,430.021152 ms** | 1.000000× |
| Registered frozen public selector | **2,405.626801 ms** | **0.989961×** |
| Retrospective zero-overhead sourcewise minimum | **2,342.703832 ms** | **0.964067×** |

The retrospective oracle chooses native for **18/60** sources; the preregistered selector chose native for **8/60**. Under these measured fixed source-level medians, **any** routing-only combination of these exact two unchanged kernels has a total time of at least **2,342.704 ms** before selector overhead. The original <0.95× workload gate would require total time below **2,308.520 ms**, which is outside this measured two-backend frontier. Its maximum idealized speed gain is **3.59%**, against the registered required **5%**. This is a finite-panel retrospective bound using observed medians, not a new prospective threshold or universal asymptotic limit.

The ten extra oracle-native instances occur among high-bit stride-4 length-3073 sources and some stride-4, 8-bit shorter sources. The registered native branch still correctly identified eight genuinely advantageous cases. Its unselected residual opportunity and 52-case routing overhead explain the missed workload-wide goal. Future attempts at a 5% gain on this source mixture require improving at least one original verifier kernel, reducing other common work, or changing the input distribution. Every such attempt needs its own source-locked preregistration.
