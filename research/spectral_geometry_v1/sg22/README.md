# SG-22: moving rational multiplier certificates

Scope: existing SG-20 finite additive routing domain, fixed shape and read budgets, and the affine effective-price/utility paths validated by SG-21 Ray.build. Let eta(s) be affine rational and A one fixed feasible schedule. The exact dual upper B(s)=eta(s)*k+sum_j max_m f_j(m,s) is convex because each adjusted component mask objective is affine in s. F(s,A) is affine. If B(s)-F(s,A)<1 at both endpoints, convexity establishes integer optimality at all intermediate integer positions, also for negative or fractional upper bounds. No guarantee is made outside the certified region or for changing read budgets or different endpoint schedules. The direction and horizon are supplied in advance for interval planning; stepwise extrapolation uses only the last two certified vectors. A secant uses exact common-denominator integers, reduced by a gcd; it rejects denominators above 1,000,000 and numerator magnitude above 10^15 at evaluation. A rejected proposal falls back to the original engine. Correction applies one reverse exact coordinate sweep on the scaled integer objective, not a new numerical LP. Every proposal is checked against a legal schedule; the best feasible objective and smallest rational bound are retained independently. Unchanged SG-20 repair and chain/direct LP and block fallback close remaining gaps. Only dual-floor-certified endpoints enter history. The moving-region arm attempts a forward interval only after a successful one-step uncorrected prediction and at least two future steps; it checks the horizon then binary searches the maximal integer prefix for that fixed schedule and affine multiplier line. Each endpoint is independently verified after timing; every reused query also receives a full independent audit. The implementation is trusted Python research code, not an untrusted execution boundary. Existing production defaults unchanged.

## Campaign

24 fresh exposed development trajectories (8 per persistent/rotating/mixed regime), d=32, T=12, budgets 7/8, 16 edited queries per trajectory, 12 pure global lambda +1 per step and 12 with the same global edit plus four distinct utility columns with one +/-1 per-step edit each. All 384 query signatures globally distinct. Two randomized whole-trajectory repetitions for six policies. Shared prevalidated ray/tasks and certified anchor construction excluded from timed queries. Process CPU includes update, extrapolation/correction, repair, solver calls, interval planning and receipt; excludes independent audit and the history update after audit, task generation and common anchor. LP-every forces a numerical LP at each query while retaining prior feasible schedule; it is not cold initialization. Fixed uses SG-21 unrestricted fixed-multiplier regions. Delta uses SG-20 warm acquisition. All policies retain the same fallbacks. Run was interrupted at tool deadline after 17 complete roots; remaining seven resumed using identical source and the saved per-root checkpoint; partial trajectory discarded. One host, two repetitions, no hard deadline or sealed confirmation cohort. Independent units are 24 trajectories. No GPU, paid inference, native model or general hardware performance claim.
