# SG-20: differential exact certificates on evolving routing tasks

Finite additive source-bound spectral routing, d<=32,T<=16. For scaled rational multipliers e/D, the upper numerator is e*k plus a sum of independent label maxima. With e,D fixed, an update changes only the budget constant and maxima of labels whose utility columns or effective last-use prices differ. Cached prefix differences also reproduce SG-14 backward rounding. Maintain the feasible schedule's per-label contribution and visit mask; an edited budget row is solved exactly conditional on all other rows, using its new cardinality and marginal last-use prices. Multiple changed rows are repaired in deterministic visit order, not jointly optimized. Only labels with changed data or changed visit masks need primal recomputation. Common coordinate translations preserve all prices. A global price or nonuniform coordinate change can invalidate every table. New multipliers rebuild the tables.

The patch interface accepts absolute replacements for u, bits, k, x, lambda within existing task bounds, rejects duplicate edits and nonmonotone coordinates, and produces an immutable new state. No caller-provided hint about changed components is trusted. The alternative full-snapshot interface validates the entire task and compares all utility columns and prices. Dimensions remain fixed; a new shape requires a rebuild. Trusted Python code constructs and retains states; frozen dataclasses are not an adversarial serialization or execution boundary. The independent SG-15 verifier checks a schedule and rational vector on the full current task. No proof checker or production default changed. Component update arithmetic O(T*|J|) excludes patch validation, per-label scans, immutable tuple copying, repeated column copies for multiple edits, and changed-budget-row sorts. Full snapshots incur O(T*d) input scanning. No global memory cap; one state per active trajectory, tables O(T*d).

## Campaign

24 fresh synthetic trajectories, eight per persistent/rotating/mixed regime, d=32,T=12, initial k=7/8. Each begins from a shared independently certified anchor, followed by 12 cumulative edits: one utility entry, four entries in one column, eight entries in up to four columns, 16 entries in up to 16 columns, one bit price, budget increase, combined utility/price/budget change, last-visit coordinate change, common coordinate translation, global lambda increase, budget decrease, 48 larger utility edits. All 288 query signatures are distinct across the cohort. Two randomized whole-trajectory arm orders per root. Every arm retains the prior feasible schedule and multiplier. Full rebuilds all fixed-vector tables after an explicit patch. Delta recomputes affected labels after the patch. Snapshot detects changes from a full task. These three use identical warm recovery and fallbacks. LP-every rebuilds the tables and requests a new LP even if the retained certificate already closes; it keeps the prior feasible schedule, so it is not cold initialization. Warm repair first checks retained schedule, then uses cached backward rounding, row sweep and bounded face recovery (512 nodes). Fallback: chain LP, direct LP, then 2048 block events if still unresolved. Numerical solver output is a proposal; exact arithmetic determines closure. No block fallback on evaluation queries. Shared anchor construction is outside query timings. Process CPU includes patch/snapshot preparation, recovery, all LP solves, exact arithmetic and receipt construction, excludes post-timing independent audit and task generation. The audit time is recorded separately. Independent statistical units are trajectories; one host, two repetitions, descriptive development, no native model performance claim.

Delta saves 71.96% of update-only dual component recomputations, 71.18% of update-only primal recomputations, and 49.73% preparation CPU versus full. These counters exclude rebuilding tables after new multiplier proposals and schedule recovery; they are not all-operation counts. Total CPU saving only 1.91% versus full with the identical warm policy (paired trajectory mean 0.07146 ms, 10,000-resample descriptive percentile interval [0.00747,0.13129] ms). Full plus independent audit 5.21362 ms vs delta plus audit 5.11086 ms. Warm acquisition avoids 330/576 LP calls; delta is 2.07x faster than LP-every, a policy comparison, not solely a cache benefit. Immediate closures 288/576; warm repair adds 42. Full/delta/snapshot receipts agree exactly on all corresponding queries. All 24 shared anchors, 2304 final receipts and 5346 stage receipts rechecked after the run; 1152 warm receipt comparisons; zero gaps on all evaluation queries. All common translation edits close immediately with zero component recalculations. Last-visit coordinate edits and lambda increases require an LP on all 48 runs of each phase. The full-snapshot path consumes much of the preparation saving. Use delta only when actual edits can be represented; otherwise validate and compare the complete task.
