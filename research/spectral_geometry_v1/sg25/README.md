# SG-25: bounded two-dimensional convex certificate memory

Scope: finite additive source-bound spectral routing, d<=32,T<=16, integer parameter points in a declared square [0,H]^2, H<=100. Fixed budgets, coordinates and bit prices. Two sparse affine utility directions and affine lambda. Nonnegative lambda and task-domain bounds are checked at all four corners; these imply validity throughout the square. Effective prices are affine because coordinates and bit prices are fixed. No arbitrary nonlinear edits, changing budgets, or extrapolative certificate claim.

For feasible schedule A and dual vector eta, the gap B(q,eta)-F(q,A) is jointly convex in affine utility/effective-price parameters and eta: it is the sum of componentwise maxima of affine relaxed mask values, less the fixed feasible schedule's affine value. Therefore a convex combination of checked vertex certificates with the same schedule and gaps <1 yields another valid integer optimality certificate. Each vertex can have its own rational multipliers. The rational chord of the vertex bounds is a valid upper bound and its floor equals the affine primal objective. This includes negative objective and fractional dual cases. Signed affine interpolation is allowed only as an untrusted proposal outside a region, never as a proof. In two dimensions, at most three vertices suffice by triangulating the convex hull; segments and singleton points are handled as degenerate cells. Exact integer determinants and barycentric numerators determine membership. Reduce rational multiplier vectors by gcd, enforce SG-15 representation caps, and reject any nonrepresentable interpolation. The verified schedule must be identical at all vertices. The proof contains vertex IDs, nonnegative integer weights and common denominator. The independent replay validates the task plane, every fresh vertex and all referenced weights, point, schedule, objective, multiplier and upper bound. Stored immutable vertices belong to a single plane; these are trusted in-process Python helpers, not an adversarial deserialization or execution boundary.

Memory holds at most 12 fresh independently verified vertices. Deduplicate positions, evict oldest insertion on overflow, group by identical schedule, compute each convex hull by monotone chain and fan-triangulate. Reused queries do not enter the vertex cache, avoiding recursively derived proof chains. Separate audit records and logs are not bounded by this retrieval cap. The prior three certified outputs (including verified derived queries) are retained for stepwise multiplier proposals. No knowledge of future query order, although the two-dimensional task family is supplied in advance. The same stepwise fallback uses the last retained feasible schedule, signed affine multiplier proposal from the last three points (or two collinear points, or the last vector), one reverse exact coordinate correction, SG-20 repair, chain/direct LP and capped block search. All proposals are checked. All arms rebuild retained-state arithmetic on a changed point; this is an SG-22-style 2D baseline, not a direct comparison to SG-20's sparse patch preparation or SG-24's one-dimensional interval planner. Recompute and region both use the identical lookup and insertion decisions; recompute explicitly builds the full state on a hit, region uses the chord alone. Independent replay occurs after the acquisition timing. On misses, warm arms include full independent verification before insertion; stepwise does not insert and its post-timing audit covers the same certificate. No production default changed.

## Campaign

24 independent exposed development trajectory roots (eight per persistent/rotating/mixed utility regime), d=32,T=12,k=7/8, 24 distinct integer queries per trajectory in [0,6]^2. 12 sparse-utility-only roots and 12 with global lambda changing along the first axis. Within each group half query the three other corners first and then 21 shuffled interior points; half query 24 randomly ordered distinct grid positions, excluding the initial anchor (0,0). There are six roots in each edit/order combination. Two randomized whole-trajectory timing repetitions per arm. Shared anchor and validated query construction outside timing. The acquisition timing includes lookup, hull maintenance, independent verification before insertion, proposals, repair, fallback and receipt; excludes post-timing audit and history update. Batches resume the same saved checkpoint, with first root executed as a smoke run and retained unchanged, then limits 8,16,24. No tuning or sealed confirmation. All 576 logical query signatures globally distinct. Independent units are trajectories, not queries or repetitions. No GPU, paid inference or native model claims.

## Independent verification and compact proof microbenchmark

Four targeted tests passed: 1600 hull membership checks against exhaustive 1/2/3-vertex subsets, 1200 tiny parameter positions (990 covered, 207 strict triangle interiors) with exact independent oracle comparisons at covered points; negative fractional chord; tampered multiplier, schedule, upper, weight and missing vertex rejection; invalid direction and coordinate inputs; denominator limits and eviction. Separate replay reconstructs all tasks independently and checks 24 anchors, 3456 final certificates, 5510 acquisition-stage receipts, 2238 proposals, 996 region receipts (620 strictly interior), 1152 paired non-timing receipt comparisons; zero blocks. The replay checks every query against full SG-15 arithmetic, and every region proof references only resident previously checked vertices. A separate proof-checking microbenchmark for the 498 region-arm hits uses the already verified resident vertex map and preconstructed current task. Five randomized repeats per query, mean of each query median process CPU: full SG-15 verify_certificate 401.281 us; compact chord check 94.287 us, 4.26x faster, wins 498/498 query medians. This measures proof-checking kernels only, excludes the initial verification/creation of vertices, the cost of storing them, task generation/validation at batch setup, acquisition, and external audit/replay. It is not an end-to-end speedup; no independent confirmation cohort. The compact check is sound only when the vertex records were previously independently verified for the same validated plane and immutable schedule. Full checks on the current task remain useful for audit.

    OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python sg25.py --limit 1
    OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python sg25.py --resume --limit 8
