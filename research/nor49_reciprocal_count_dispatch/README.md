# NOR-49: count-R≥2 exact signed-program dispatch

The first [timing-prospective protocol](REGISTRATION.md) was frozen in commit `26b70716ec3d3830031919e593d3092cc31ae162`, before evaluating any source-specific CPU timings from the 48 heldout source identities. Original [NOR48 first negative CPU result](https://github.com/MoralityLabAI/Compactification-Theory/blob/main/research/nor48_program_dispatch/RESULTS.md) is the only timing TRAIN evidence.

Among 16 original previously timed signed-native programs, the source-authorized reciprocal count predicts backend advantage more sharply than presence of any reciprocal operation. **Seven** original programs have two or more active R operations and each achieved NOR48 GMP/direct <0.75×; **five** contain exactly one active R and each achieved ≥0.785×, while all four no-R cases are direct. The frozen NOR49 decision rule is `count_R(base,u,v,active_hidden_transform) ≥ 2 → GMP full exact trace`; all others select NOR45 full direct. The output vector and Merkle root must match every exact signed reference program in either branch. The model cannot supply a backend hint, use true target coefficients or offer trace statistics to change routing.

The first 48 timing-clean source identities are the original NOR42 archived public pairs from 12 replicate blocks other than 100,104,108,112. They were originally generated and graded before NOR45–48. Their CPU timing outcomes were excluded from every earlier backend benchmark. Separate [cohort.py](cohort.py) must generate and upload a fixed roster-only SHA artifact before any first timing; neither a new source identity nor future target is generated. A second dependent job runs exactly five interleaved repetitions of four full output+Merkle-root arms: NOR45 direct, NOR47 full GMP exact trace, NOR48 any-R, and NOR49 R-count≥2. First registered engineering gates test **median NOR49/direct <0.75×**, **median NOR49/NOR48 <0.95×**, signed-program routing purity, all exact output/root parity, and source-first reproducibility.

All signing/precommit/session/provider verification is subject to pinned independent keys. The arithmetic-only CPU comparisons exclude the common signature and network costs equally; [selector.py](selector.py) exposes a full signed path for functional and negative tests. The underlying exact execution remains nonsuccinct and does not prove program-authority honesty or external semantic truth.

**First holdout CPU run:** this README commit triggers the source-only timing-clean roster job, followed by the initial fixed five-repeat evaluation. The original first raw SHA, performance PASS/FAIL, source-level measurements and 12-block descriptive uncertainty will be archived as scored without retuning.
