# NOR-48: signed-program R-aware exact verification benchmark

The original historical engineering protocol was fixed at [DESIGN.md](DESIGN.md) before any new NOR48 timing. The source cohort is the **16 previous NOR46 original SHA-archived source programs** from replicate blocks 100,104,108,112, with 12 whose authorized program uses reciprocal operation R and four without R. The original NOR47 result receipt, 34,928 bytes SHA256 `809fd5d18cfb61e4e6d771c4e402b31e3fec99889774f4305ddfa3d6c793f530`, provides independent source identities and the original R/no-R split.

[dispatcher.py](dispatcher.py) computes the routing decision from the already independently signed authorized program only: presence of `R` in base/u/v or active hidden transform selects the **reentrant locally injected GMP convolution**. All no-R programs select direct NOR45 exact execution. Both compute a full exact signed-coefficient continuation and a fresh Merkle root. Wrong traces are rejected by the R path and ignored by the direct path; an unsigned backend hint cannot change execution. The code deliberately distinguishes this verified arithmetic core from the surrounding NOR44 verifier precommit, NOR45 signed native statement, and NOR43 provider-reference authentication, which remain external prerequisites in the historical benchmark.

The original fixed benchmark compares **NOR45 direct + root**, **NOR46 original Python full trace + root**, **NOR47 explicit GMP full trace + root**, and **NOR48 signed-program-aware dispatch + root**, in five source-seeded interleaved repetitions on each of the same 16 programs. All signature/session/network costs are excluded equally, as specified in [NOR48 issue #251](https://github.com/MoralityLabAI/Compactification-Theory/issues/251). The first engineering target is median **sourcewise NOR48/NOR45 < 0.75** with all four no-R cases dispatching to the direct path, 12 R cases to GMP and exact vector/root parity everywhere. The raw original first-run JSON will be retained even if the measured target fails.

The explicit convolution injection prevents the global NOR46 verifier's multiplication function from changing, including when the injected backend raises. A future application-facing signed-verification API would need to integrate the full NOR44–46 signature/session context and side-effect controls. The present benchmark is transparent exact execution, not cryptographic succinctness or an external correctness oracle.

The original raw output hash, engineering verdict and source-block uncertainty will be reported separately without changing the protocol.
