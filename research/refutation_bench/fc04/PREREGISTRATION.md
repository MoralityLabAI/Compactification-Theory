# FC-04 preregistration: validation-calibrated recurrent halting

**Registered 2026-11-13 before FC-04 dataset generation, model adaptation, or test inspection.**

This experiment studies whether a small, already-trained LR-01 graph reasoner can choose when to stop iterating and issue verified refutation certificates more efficiently. A **fresh family-held-out** finite Horn test is required because FC-03 results, seeds, and extrapolation-depth behavior were already inspected.

## Frozen inputs and access boundary

- Existing FC-02 generator source: commit `7aca2bc3fc5586c5b7997fba868bd179db761121`; canonical 1,536-case SHA-256 `8e86a41dd93ff162072799332ebbef4c7134951798eb4af7ebb4ab044bebd56f`.
- Original model architecture: tied LR-01 `TypedLoop` in `LoopedTransformers/experiments/lean_reasoner/train.py`, `LoopReach` from FC-02, **11,521 parameters**.
- Train frozen models from scratch on FC-02 train only: seeds **17** and **29**, 4 recurrent passes, AdamW lr 0.002, weight decay 0.01, 350 steps, batch 48, gradient clipping 1, two CPU threads, deterministic torch.
- Fit only the **stopping threshold** from FC-02 development (192 cases); freeze both network weights and the selected threshold before any FC-04 test checkout.
- New FC-04 test generator must never exist in training or calibration job. Evaluation is a dependent second GitHub Actions job loading SHA-256-checked weights, calibration receipt, then the pinned test generator.

## New families, splits and verification

FC-04 must provide **384 never-trained cases**, in two 192-case splits: `test_same` at depth **2–4** and `test_deep` at depth **6–8**, with **96 valid and 96 invalid** in each. Four entirely new graph construction grammars: `relay_deadlock`, `asymmetric_fork`, `stacked_join`, and `gated_detour`. Each supplies 24 valid and 24 invalid per split. Generator root seed `20261113`, offset IDs `62003` and `73009`, with deterministic attempt-index seeds and a shared WL structural-fingerprint rejection set against FC-02 (1,536), FC-03 (384) and all accepted FC-04 cases. Case count, depth range, family and label balance, and fingerprints are asserted.

The finite Horn closure implementation and exhaustive propositional truth-table verifier must agree on every label. Every negative sample must carry a complete Boolean assignment satisfying all premises and falsifying the goal. Every positive sample must produce an explicit Lean 4.19.0 theorem proof term. The source CI must compile **192** positive proofs and independently validate **192** negative certificates. These checks concern bounded propositional arguments only.

## Pre-registered stopping policy

Candidate inference checkpoints are **4, 6, 8, 10, 12** tied-cell applications. At every checkpoint, obtain goal probability and a Boolean assignment from the model's atom logits, each atom true iff sigmoid(logit) >= 0.5.

1. A negative verdict may be released **only** if the *independent exact checker* verifies that exact model-proposed complete assignment (premises all true, conclusion false). Stop immediately on a verified countermodel. This is a post-inference filter, not a model-repair oracle.
2. For an uncertified **positive** call, accept `established_provisional` only after the goal probability exceeds threshold θ at **two consecutive** checkpoints. This output is explicitly provisional because a Lean proof term is not generated by the model.
3. If no condition is satisfied at 12 passes, **abstain**. The policy never emits an unverified `refuted` call.

Select θ on FC-02 development, after fitting network weights, from the **fixed grid** `[0.55, 0.70, 0.85, 0.93, 0.98]`. Predefined objective: maximize `(correct_certified_refutations + correct_provisional_positives - 5 × wrong_provisional_positives - 0.01 × total_cell_calls) / N` on FC-02 development. Ties choose the *higher* θ. This calibration uses only existing dev labels and is performed before the frozen FC-04 test is accessible. Preserve every grid score.

The model runner must implement **real early exit**. It may not compute all 12 passes and then retrospectively count fewer passes as saved computation. CPU forward milliseconds include only the operations actually performed. Report checker calls/time separately, so verifier cost is charged.

## Frozen baselines and primary metrics

- `fixed4`, `fixed8`, `fixed12`: execute exactly that many passes; release a `refuted` verdict only with an exact certificate, else issue `established_provisional` if its goal probability exceeds the same calibrated θ, else abstain.
- `adaptive`: policy above with early counterexample exit and two-checkpoint positive stability.
- `cert_only_first`: early verified-counterexample exit at checkpoints 4,6,8,10,12, abstain otherwise; exposes exact certificate gain independent of provisional positive acceptance.
- `always_abstain` baseline for calibrated-selective risk.
- Exact forward-chaining oracle (100% truth in this finite Horn fragment) as a labelled **symbolic upper bound**, never represented as neural performance.

For each split and model seed report: certified-refutation recall on 96 invalid cases, accepted negative certificate soundness, provisional-positive correct/wrong counts, selective coverage and selective error rate, abstentions, mean/median/p95 **actual** recurrent calls, measured CPU forward milliseconds per case, exact checker call count and elapsed milliseconds, and a utility using the same equation as validation. Compare adaptive against every frozen-pass baseline in **certified invalid examples per 1,000 recurrent cell applications**, and total CPU time. Preserve raw, per-case predictions, stopping reasons and cumulative calls. Expose per-family breakdowns.

**Primary decision:** Adaptive inference counts as an improvement only if on both new test splits and both seeds it attains at least the `fixed12` certified-invalid recall, uses fewer mean recurrent calls, and has no verified false counterexamples or increased provisional-positive error rate. Otherwise report mixed/negative; no test-driven threshold or pass-count changes.

## Boundaries

This is a public pre-registered synthetic graph-family test, not a cryptographically secret blind test. The historical RH, Fermat, four-colour, P vs NP and Collatz manuscripts remain outside the training and test domains. The full finite Horn oracle would solve these tasks exactly, so a compact student cannot claim better correctness than that oracle. Recurrence halting here is an efficiency/transfer experiment, with no proven connection to general mathematical refutation until a separately validated semantic encoder and raw-source evaluation exist.
