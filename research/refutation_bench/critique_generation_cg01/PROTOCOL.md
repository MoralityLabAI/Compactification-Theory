# RB-CG-01: generate independently checkable critiques of Lean submissions

## Motivation and scope
RefutationBench LR-01 (36,682 parameters, six synthetic training examples) emitted a canned explanation and falsely rejected 8–9/9 non-refuted public dev examples. SA-03's learned acquisition criterion failed (GRU totals 41,46 vs DFS 44 on the 16/32-read deeper tests). This campaign adds an autoregressive, model-generated critique certificate, including a dependency path and a concrete valuation when required. The English report is a deterministic rendering of the generated certificate. No claim of free-form mathematical prose generation or arbitrary Lean auditing follows.

## Source and splits
Use 384 fresh independent families (256 train, 32 calibration, 48 depth transfer, 48 held-out mutation transfer; seeds 101701/101702/101703/101704), 8 submissions per source, 3072 total. Each raw Lean module has a finite Boolean formula theorem, a clean proof root and a separate axiom-dependent root, randomized opaque names, interleaved aliases and dead axioms. Cross both roots with four advertised targets: matching type, false target, valid supplied nondefinitional bridge, independently true target without a supplied named bridge. The last has status unestablished under the explicit supplied-link contract, not false or unprovable. Familiar counterexamples remove an antecedent, reverse an implication, or strengthen a consequent; held-out mechanisms use a vacuous source antecedent or an unrelated predicate. All source families stay in one split; deeper aliases are outside train range. Public synthetic held-out data, not blind.

Source proof and every advertised proposition are exact finite Boolean formulas over three variables. All selected source declarations compile, including those with extra assumptions; no admitted proofs. Use Lean 4.19.0 native checks of clean and tainted root axiom closures, supplied bridge and clean bridge application, independently true unlinked target, and every falsifying Boolean valuation. This corroborates generated source metadata; a general-purpose Lean dependency extractor is not implied. The independent parser operates only on the raw generated grammar, without gold or generator metadata, and is a deterministic upper bound for this fragment.

## Generated output
The decoder produces a complete variable-length certificate:
CLEAN or AX followed by declaration line pointers along the complete single-chain dependency path to the relevant root leaf, then SEP followed by MATCH, BRIDGE and bridge line, COUNTER and three Boolean values, or UNLINKED, then EOS. CLEAN requires the exact axiom-free proof chain. AX requires a real reachable forbidden axiom. COUNTER requires a falsifying valuation of the advertised target, not merely a mismatch. MATCH/BRIDGE require the supplied connection. UNLINKED requires a true advertised proposition and absence of the named source link under the closed fixture contract. A deterministic prose renderer may quote only the emitted certificate and actual input source. For rejected certificates show the proposed critique only with an explicit verification failure. Never upgrade an unlinked statement to falsity, an axiom use to inconsistency, or the presence of a dead axiom to a dependency. A valid certificate can contain two independent findings; report each axis and their conjunction. No reference labels, gold paths, witness bits or hidden metadata in model input.

## Learning and baselines
Normalize opaque identifiers by first appearance in raw input, including the selected root and target query. Tokenize Lean source and preserve line pointers; do not expose parsed dependency labels or truth tables. Train a line-encoding attention GRU decoder with widths 32 and 80, seeds 41/43, ten fixed epochs, teacher-forced token cross entropy, CPU AdamW at 0.003, minibatch 32, no checkpoint selection on heldout data. Training target uses a deterministic canonical valid witness; verifier accepts any genuine counterexample. Greedy decode without semantic repair, and report malformed outputs. Baselines: constant most frequent training certificate skeleton (invalid dynamic pointers are retained), lexical nearest training input with its certificate copied verbatim, independent raw-source symbolic parser. No model inference or symbolic policy may read gold. Report heldout verified complete critique rate, verified individual axes, invalid or malformed outputs, false accusations on supported controls, valid support coverage, unlinked coverage, total generated token count, parameter/checkpoint hashes and CPU time. Primary feasibility gate: at least 50% fully verified heldout critiques on both splits and at most 5% false defect claims on genuinely supported controls for both seeds of a width; compare explicitly to the exact symbolic parser, with no superiority claim from a pass. Width 80 is an exploratory size comparison under the same fixed protocol. The 7M model and natural-language generation are deferred.

## Later genuine proof critique
Add raw source fragments from independently pinned real Lean developments, non-finite theorem types and imported dependency closure. Test honest conditional proofs, vacuity claims with and without an existence advertisement, omitted bridges, real countermodels, and repaired controls. For actual novel critiques require independent native evidence and scope-aware human review. The historical Nielsen family remains development-only. Do not reward a convincing explanation without a justified finding.
